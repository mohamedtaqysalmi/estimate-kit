Turn a project brief into hour ranges, then check every row yourself.

A single number for a quote hides how wrong it might be. I wrote this to turn a Markdown brief into best, likely and worst hours per task, with risks and assumptions, and to make me review each estimate before anything is exported. It runs offline on keyword rules; an LLM path exists but is off unless you switch it on.

Range calculator

Enter best, likely and worst hours for each task. Each task gets an expected value (best + 4 x likely + worst) / 6 and a spread (worst - best) / 6. The total adds the expected values and combines the spreads as the square root of the sum of squares. This is the same math as the Python package, checked against shared test vectors in site/range-vectors.json.

How not to trust this tool

  • The hour figures in rules.toml are my rough starting points. They are not measured from past projects and have not been calibrated against delivery times.
  • Categories come from keyword matching, not from understanding the task. Check the Category column.
  • The plausible range assumes tasks are independent. One wrong assumption about a client's data or approvals can slow many tasks together.
  • Anything the brief does not mention is not estimated: testing by others, meetings, revisions, content and project management.
  • The output is a draft. Read every row, change what you disagree with, and do not send it to a client unchecked.

What works

  • works Brief parsing: headings become sections, bullets become tasks, skippable sections are reported
  • works Rule-based ranges with risks and assumptions, all numbers in one TOML file
  • works Review step: accept, edit or drop each task. Without it, output is marked unreviewed
  • works Markdown and CSV export
  • partial LLM path behind ESTIMATE_KIT_LLM=1. Tested against mocked responses only, never against a live provider
  • not done Calibration of the hour figures against real projects, and a PyPI release

Quickstart

git clone https://github.com/mohamedtaqysalmi/estimate-kit
cd estimate-kit
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
estimate-kit estimate examples/riad-booking.md

On Windows, activate with .venv\Scripts\Activate.ps1. The command asks you to accept, edit or drop each task before it prints anything.

How it works

Each bullet becomes a task. The first matching category in rules.toml sets the three hour figures, and modifiers such as real-time or multilingual scale them. Ranges combine with the PERT formulas above, and nothing is exported until you have been through the review. 

brief.md
   │
   ▼
parse headings and bullets ──► tasks
   │
   ▼
keyword rules (default)   or   LLM (ESTIMATE_KIT_LLM=1, falls back to rules)
   │
   ▼
best / likely / worst per task, risks, assumptions
   │
   ▼
review: accept, edit or drop each task
   │
   ▼
Markdown or CSV

How I built it

Every number lives in one file

The hours, keywords, risks and assumptions are in rules.toml. If you disagree with a figure you can see where it came from and change it.

Ranges, and a total that is not a naive sum

Adding every worst case assumes everything goes wrong at once. The total uses PERT expected values and combined spreads, and the summary still shows the plain sums next to it so the gap is visible.

The review is not optional

Skipping it is possible only with --skip-review, and then the output says it was not reviewed. I would rather the tool be slightly annoying than produce a polished number nobody checked.

The LLM is a fallback-protected extra

It is off by default, the prompts are versioned in prompts/v1/, and any failure falls back to the rules.

Limits and roadmap

  • Only bullet lists under headings are read. Tables, prose requirements and several features in one bullet are not understood.
  • Keywords are English only.
  • No estimate here has been compared with how long the work really took.

Open work is tracked in the issues. To contribute, start with CONTRIBUTING.md.
